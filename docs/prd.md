# 교수님 일정 트래킹 시스템 PRD

- 문서 버전: v1.0
- 작성일: 2026-08-07
- 문서 목적: 연구실 내부에서 교수님의 재실/부재 여부를 공유하기 위한 주간 일정 트래킹 시스템의 요구사항 정의

---

## 1. 제품 개요

### 1.1 제품 목적

교수님의 구체적인 업무 내용이나 개인 일정을 기록하지 않고, 연구실원이 교수님의 **재실 여부와 부재 시간만 공유**할 수 있도록 하는 내부 일정 트래킹 시스템을 제공한다.

교수님은 매우 바쁜 일정으로 움직이므로, 연구실원은 주간 캘린더를 통해 특정 시간에 교수님이 계실 가능성이 있는지 빠르게 확인할 수 있어야 한다.

### 1.2 핵심 원칙

1. **일정 내용은 기록하지 않는다.**
   - 미팅, 출장, 휴가, 작업 등의 구체적인 사유를 저장하지 않는다.
   - 시스템에서 관리하는 핵심 정보는 시간과 부재 여부이다.

2. **기본 상태는 흰색이다.**
   - 흰색은 '교수님이 계신다(ON)'라는 의미가 아니다.
   - 별도의 부재 정보가 등록되지 않은 기본 상태이다.

3. **부재가 확인된 경우에만 색상으로 표시한다.**

4. **하루 전체 부재와 특정 시간 부재를 구분한다.**

5. **연구실 구성원만 서비스를 이용할 수 있다.**

- 사용자 인증/관리
- 전체 부재 정보 관리
- 잘못 등록된 정보 수정/삭제

※ 관리자 기능의 상세 범위는 개발 단계에서 확정한다.

## 4. 하루 전체 부재 기능

### 4.1 날짜별 ON/OFF 토글

주간 캘린더의 각 날짜 최상단에 하루 전체 상태를 제어하는 토글을 배치한다.

예:

| | 월 | 화 | 수 | 목 | 금 |
|---|---|---|---|---|---|
| 전체 부재 | ON | ON | ON | OFF | ON |

### 4.2 기본값

- 모든 날짜의 기본값은 `ON`
- 단, `ON`은 캘린더의 시간 영역을 색칠한다는 의미가 아니다.
- `ON`은 **하루 전체 부재가 등록되지 않은 기본 상태**를 의미한다.
- 따라서 `ON`인 날짜의 시간 영역은 그대로 흰색으로 표시한다.

### 4.3 OFF 설정

인증된 연구실원은 교수님과 직접 이야기했거나 확실하게 확인한 경우 해당 날짜를 `OFF`로 변경할 수 있다.

예:
- 출장
- 휴가
- 하루 종일 외부 일정
- 기타 종일 부재

단, 부재 사유 자체는 입력하지 않는다.

### 4.4 OFF 시각화

날짜가 `OFF`이면 해당 날짜의 09:00~21:00 전체 영역을 부재 상태로 시각적으로 표시한다.

## 5. 특정 시간 부재 기능

### 5.1 시간 범위 등록

인증된 연구실원은 특정 날짜의 특정 시간 범위를 부재로 등록할 수 있다.

예:
- 14:00~16:00 부재
- 17:00~18:30 부재

### 5.2 등록 방식

사용자는 캘린더에서 원하는 시간 영역을 선택하여 부재를 등록한다.

등록 시 필요한 정보:
- 날짜
- 시작 시간
- 종료 시간

등록하지 않는 정보:
- 부재 사유
- 미팅 상대
- 업무 내용
- 장소
- 기타 개인 일정 정보

### 5.3 시각화

특정 시간 부재가 등록되면 해당 시간 영역만 색상으로 표시한다.

예:

| 시간 | 수요일 |
|---|---|
| 13:00 | |
| 14:00 | 부재 |
| 15:00 | 부재 |
| 16:00 | |
| 17:00 | |

---

## 6. 상태 및 시각화 규칙

| 상태 | 캘린더 표시 | 의미 |
|---|---|---|
| 기본 | 흰색 | 등록된 부재 정보 없음 |
| 시간 부재 | 색상 영역 | 특정 시간대 부재 |
| 종일 부재 | 해당 날짜 전체 색상 | 하루 전체 부재 |

### 중요한 규칙

- 흰색을 `ON`으로 정의하지 않는다.
- 시간 영역에 별도의 `ON` 텍스트를 표시하지 않는다.
- 부재 사유를 색상이나 텍스트로 구분하지 않는다.
- 종일 부재는 상단 토글의 `OFF`와 전체 시간 영역의 색상으로 표현한다.

## 7. 제보 및 데이터 원칙

### 7.1 제보 중심 시스템

본 시스템은 교수님이 직접 자신의 일정을 관리하는 일반적인 캘린더가 아니다.

연구실원이 알고 있는 정보를 바탕으로 교수님의 부재를 **제보하고 공유하는 시스템**이다.

### 7.2 제보 기준

사용자는 다음과 같이 확실하게 확인한 경우 부재를 등록할 수 있다.

- 교수님에게 직접 들은 경우
- 교수님의 일정에 대해 확실하게 알고 있는 경우

단순한 추측이나 예상은 등록하지 않는 것을 원칙으로 한다.

### 7.3 개인정보 및 사생활 보호

시스템에는 교수님의 구체적인 일정 내용을 기록하지 않는다.

예를 들어 다음과 같은 데이터는 저장하지 않는다.

- '14시 외부 업체와 미팅'
- '15시 교수님 개인 일정'
- '목요일 부산 출장'
- '학생 A와 상담'

대신 다음과 같이 부재 정보만 저장한다.

- `14:00~16:00 OFF`
- `목요일 ALL DAY OFF`

## 10. 충돌 및 우선순위

### 10.1 종일 OFF와 시간 부재

하루 전체 상태가 `OFF`인 경우 해당 날짜는 종일 부재 상태이므로 **특정 시간 부재를 추가로 등록할 수 없다.**

- 해당 날짜의 `OFF` 상태가 유지되는 동안 시간 영역 선택 및 시간 부재 등록 기능을 비활성화한다.
- 이미 등록된 시간 부재 정보가 있는 상태에서 하루 전체를 `OFF`로 변경하는 경우, 기존 시간 부재 정보는 별도로 유지하지 않고 종일 부재 상태로 통합한다.
- 종일 `OFF` 상태에서는 해당 날짜의 시간 부재 수정/추가 기능을 사용할 수 없다.

### 10.2 종일 OFF 상태에서 ON으로 변경

하루 전체 토글을 `ON`으로 변경하면 해당 날짜의 종일 부재 표시를 제거한다.

종일 `OFF`로 변경하기 전에 기존 시간 부재 정보가 있었다면, 해당 정보는 삭제되는 것으로 처리한다. 따라서 `ON`으로 다시 변경한 이후에는 시간 부재가 없는 기본 상태가 된다.

예:

```text
전체 상태: OFF

→ 해당 날짜 전체 부재
→ 시간 부재 등록 불가
```

이후:

```text
전체 상태: ON

→ 기본 흰색 상태
→ 필요한 경우 새로운 시간 부재 등록 가능
```

## 12. UX 요구사항

### 12.1 빠른 확인

사용자는 메인 화면에 진입하자마자 이번 주 교수님의 부재 여부를 확인할 수 있어야 한다.

### 12.2 빠른 제보

특정 시간 부재 등록은 가능한 한 적은 단계로 완료되어야 한다.

권장 흐름:

```text
시간 영역 선택
→ 부재 등록
→ 캘린더에 즉시 반영
```

### 12.3 종일 부재 등록

권장 흐름:

```text
날짜 상단 ON/OFF 토글
→ OFF 선택
→ 해당 날짜 전체 부재 표시
```

### 12.4 불필요한 정보 최소화

사용자가 부재 사유를 입력하도록 요구하지 않는다.

---

## 13. 비기능 요구사항

- 연구실 내부 사용을 전제로 한다.
- 인증되지 않은 사용자가 일정 정보를 조회할 수 없어야 한다.
- 등록 및 수정 결과는 가능한 한 즉시 캘린더에 반영되어야 한다.
- 여러 연구실원이 동시에 접근해도 데이터 정합성을 유지해야 한다.
- 부재 정보에는 필요한 최소한의 데이터만 저장한다.

## 14. 핵심 사용자 시나리오

### 시나리오 A — 주간 일정 확인

1. 연구실원이 로그인한다.
2. 이번 주 캘린더를 확인한다.
3. 기본 영역은 흰색으로 표시된다.
4. 부재가 등록된 시간만 색상으로 표시된다.
5. 특정 시간에 교수님이 계실 가능성을 확인한다.

### 시나리오 B — 특정 시간 부재 등록

1. 연구실원이 교수님으로부터 특정 시간 부재 정보를 전달받는다.
2. 해당 날짜와 시간 영역을 선택한다.
3. 부재를 등록한다.
4. 해당 시간 영역이 색상으로 변경된다.
5. 다른 연구실원도 변경 내용을 확인할 수 있다.

### 시나리오 C — 종일 부재 등록

1. 연구실원이 교수님에게 하루 종일 부재라는 사실을 확인한다.
2. 해당 날짜의 상단 토글을 `ON → OFF`로 변경한다.
3. 해당 날짜의 전체 시간 영역이 부재 색상으로 변경된다.
4. 다른 연구실원도 해당 날짜가 종일 부재임을 확인할 수 있다.

## 15. 제품의 핵심 정의

> **교수님의 일정 내용을 기록하는 캘린더가 아니라, 연구실 구성원이 교수님의 부재 여부를 빠르게 공유하고 확인하기 위한 내부 주간 트래킹 시스템이다.**

핵심 UX는 다음과 같다.

```text
                 주간 캘린더

          월      화      수      목      금
전체      [ON]    [ON]    [ON]    [OFF]   [ON]
──────────────────────────────────────────────
09:00      │       │       │███████│       │
10:00      │       │       │███████│       │
11:00      │       │       │███████│       │
12:00      │       │       │███████│       │
13:00      │       │       │███████│       │
14:00      │       │       │       │       │
15:00      │       │       │███████│       │
16:00      │       │       │███████│       │
17:00      │       │       │       │       │
...
21:00      │       │       │       │       │

기본 = 흰색
특정 시간 부재 = 해당 시간만 색상
종일 부재 = 상단 OFF + 해당 날짜 전체 색상
```

이 문서를 MVP 개발을 위한 제품 요구사항 정의서(PRD)로 사용한다.
